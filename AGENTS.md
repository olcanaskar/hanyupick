# HanyuPick — agent guide

An Expo/React Native app (**SDK 57**) for studying HSK 1-6 vocabulary: a fixed library of 5,000 words (ids 1-5000, six levels; **all six levels follow the official Hanban 2012 lists** — 150 + 150 + 300 + 600 + 1300 + 2500 words, see `NOTES.md` §10, §9, §8), 6 quiz directions, a mistake-review pool, custom decks imported from JSON, vocabulary search with handwriting input, a stats screen, and a settings pop-up (vibration, speech volume, reset progress, GitHub link).

Names: the app is **HanyuPick** (`app.json` `name`/`slug`, store identifiers **`io.github.olcanaskar.hanyupick`** — the `io.github.` prefix ties the namespace to the globally unique GitHub handle), the git repository is **`olcanaskar/hanyupick`**, the Expo/EAS project is **`@olcanaskar/hanyupick`** (GitHub and Expo accounts share the name `olcanaskar`), and the **local working folder is still `C:\Projects\App\ChineseQuizApp`** — folder renames only happen when the user asks.

**TypeScript** for all logic — `services/`, `__tests__/` and the example-sentence data in `data/examples/` are `.ts`; the screens, components and `App.js` are still `.js`/JSX and are type-checked through `checkJs`. Navigation is **React Navigation (Stack)**, not Expo Router.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json` (currently `expo ~57.0.30` → **SDK 57**).
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v57.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

This project uses npm (`package-lock.json`; there is no `bun.lock`) — use `npx`.

```bash
npx expo install <package>          # ALWAYS use instead of npm/yarn/pnpm add — resolves SDK-compatible versions
npm run lint                        # ESLint over the whole project (flat config) — 0 errors expected
npm test                            # jest (jest-expo preset) — 247 tests, 14 suites
npm run tsc                         # tsc --noEmit over the .ts logic and the JS screens (checkJs) — 0 errors expected
npx expo start --go --clear         # dev server for Expo Go (no native build needed)
npx expo-doctor                     # dependency/config diagnosis — currently 20/21 (see NOTES.md §16); needs git on PATH
npx expo install --fix              # fix incompatible package versions
npx expo export --platform android  # bundle pre-check; writes dist/ (gitignored) — delete afterwards
npx expo export --platform web      # web build (the second platform, Faz 24); same dist/, delete afterwards
npx expo start --web                # web dev server (react-dom + react-native-web + @expo/metro-runtime)
```

`npm test`, `npm run lint` and `npm run tsc` must all pass before a task is declared done.

> Do **not** use `npx expo lint` here: it only lints `/src`, `/app` and `/components`, while this project keeps its screens in `screens/` and its logic in `services/`, so it silently skips most of the code. Use `npm run lint` (which runs `eslint .`).

Single sources of truth — never duplicate these elsewhere:

- `services/wordRepository.ts` — levels and word pools: `LEVELS`, `LEVEL_LABELS`, `LEVEL_POOLS`, `ALL_WORDS`, `getWordPool()`, `getWordById()`, `getLevelFromWordId()`.
- `services/reviewPool.ts` — the mistake pool's single record shape (`{ wordId, wrongMode }`; `snapshot` only for custom-deck words) plus its helpers. `normalizeReviewPool(raw, idMap)` remaps merged word ids **before** resolving (an id that no longer exists in the data would otherwise be silently dropped).
- `services/wordIdMigrations.ts` — the ONLY record of every word-id move: **Faz 4** `MERGED_WORD_ID_MAP` (the 17 duplicated `hsk5` records: removed id → kept id), **Faz 6** `HSK5_REBALANCE_ID_MAP` (old `hsk5` tail id → the id where that word lives now: another `hsk5` id or its `hsk6` id) + `HSK5_REBALANCE_DROPPED_IDS` (words that left the library), and **Faz 7** `HSK14_REALIGN_ID_MAP` (old `hsk1-4` id → the word's current id: another `hsk1-4` id, an `hsk5`/`hsk6` id for words the official list puts higher, or the pattern entry a lone word was absorbed into) + `HSK14_REALIGN_DROPPED_IDS` (words in no official HSK 2.0 level). Word ids are identity, so deleting an entry (or reshaping the data) without migrating `@hsk_user_stats` and `@hsk_review_pool` loses or misattributes user progress. `WORD_ID_MIGRATIONS_BY_VERSION` maps each phase to its own table and `getPendingWordIdMigrations()` returns only the phases newer than `@hsk_word_id_migration_version`; `App.js` applies them at startup **in ascending order** (`mergeWordStatsIds(map)`, `removeWordStatsByIds(dropped)`, `normalizeReviewPool(pool, map)`) and only then calls `markWordIdMigrationsApplied()`. The ascending order is load-bearing: 30 ids are both a Faz 6 source and a Faz 7 target, so the combined table (or a wrong order) would move a new word's progress to the wrong id. Never call `mergeWordStatsIds`/`normalizeReviewPool` with these tables outside that flow.
- `services/exampleService.ts` — the only place that maps a word id to its example sentence (`EXAMPLES_MAP` per level, keyed by word id). When words move or change, their example keys must move with them: an orphan key would show another word's sentence (`__tests__/exampleService.test.ts` asserts none exist). Coverage is now complete across all six levels: hsk1-4 1200/1200 (Faz 8 wrote the sentences Faz 7 left out), hsk5 1300/1300 (Faz 9 wrote the 638 missing ones and fixed 22 mis-keyed records), hsk6 2500/2500 (Faz 10 wrote the 1945 missing ones and rewrote the 385 mis-keyed/defective records) — 5000/5000. `getExampleByWordId()` still returns `null` for an id with no entry (e.g. custom-deck words) and `ExampleBox` renders nothing. In every level the example's `hanzi` must contain its word literally (`__tests__/exampleService.test.ts` asserts this for all six levels since Faz 13; multi-part pattern words such as `虽然……但是……` are exempt, because an ellipsis notation can never appear verbatim in a sentence).
- `services/modes.ts` — the 6 quiz directions and their 3 categories. Everything (`MODES`, `CATEGORIES`, `MODE_CATEGORY`, `MODES_BY_CATEGORY`, `MODE_LABELS`, `DEFAULT_MODE`, `getCategory()`, `getCategoryIndex()`, `getPromptType()`, `getAnswerType()`, `getReverseMode()`, `getHintField()`) is derived from ONE table at the top of the file. Never parse a mode name with `startsWith`/`endsWith` and never hardcode a category key elsewhere.
- `services/dateUtils.ts` — the only place that builds day keys (local time, never UTC).
- `services/statsManager.ts` — the stats record shape plus the mastery rules (`MASTERY_STREAK`, `isMastered`, `isProblematic`, `getMastery`). They apply to HSK ids (numbers) and custom-deck ids (`custom_…` strings) alike; never re-implement them in a component (they lived in `StatsModal` until 3.6b, where they were untestable). Every write goes through ONE queue (`recordAnswer`, `removeWordStatsByIds`, `clearAllStats`, `mergeWordStatsIds`) so concurrent writes cannot clobber each other — never write `@hsk_user_stats` directly.
- `services/handwritingService.ts` — the ONLY place that talks to the external handwriting API (`recognizeHandwriting()`, `buildInk()`). It owns the timeout, so callers never `fetch` directly and must handle its `{ candidates, error }` result (`error` is `null | 'timeout' | 'network'`) instead of catching network errors themselves.
- `services/floatingParticles.ts` — the floating-Hanzi geometry and motion (`getRandomBoundaryPoint`, `pickTargetPoint`, `createParticle`, `PARTICLE_COUNT`, size/speed bounds). Randomness is injectable and the target search is **bounded** (`MAX_TARGET_ATTEMPTS`) — never put this math back into `FloatingBackground`, and never replace the bounded search with a bare `while` (that was an unguarded loop that could freeze the JS thread). The component supplies the live window size (`useWindowDimensions`), never a module-load snapshot of `Dimensions`.

- `services/settingsService.ts` — the user settings record (`{ haptics, speechVolume }`), defaults and validation, under `@hsk_settings`. `getSettings()` reads the disk (missing/corrupt fields fall back per field, unknown fields are dropped), `updateSettings(patch)` merges, emits `SETTINGS_CHANGED_EVENT` and then persists, and `getCachedSettings()` returns the in-memory copy **synchronously** — `Speech.speak` cannot await storage, so every reader (speech/haptics services, the settings screen) goes through this module.
- `services/speechService.ts` — the ONLY place that calls `expo-speech` (`speakHanzi`, `stopSpeaking`, `warmUpSpeech`). It attaches the user's `speechVolume`, so the quiz card's 🔊 and the vocabulary 🔊 behave identically; callers never pass `volume` themselves. `warmUpSpeech` deliberately speaks at `volume: 0` (independent of the setting).
- `services/hapticsService.ts` — the ONLY place that calls `expo-haptics` (`selectionFeedback`, `failureFeedback`). Both are no-ops while `settings.haptics === false`, so the vibration toggle covers every call site.
- `services/dialogService.ts` — the ONLY place that shows a one-button message box (`showAlert(title, message)`): `window.alert` on web, `Alert.alert` on native. `react-native-web` ships a deliberately empty `Alert` (`static alert() {}`), so a direct `Alert.alert` fails **silently** on the web build. All confirmations stay in-modal by design (there is no `showConfirm`).

AsyncStorage keys: `@hsk_review_pool`, `@hsk_user_stats`, `@custom_word_decks`, `@hsk_word_id_migration_version` (the applied id-migration version, not user progress), `@hsk_settings` (user settings).

## Type checking

- `npm run tsc` runs `tsc --noEmit`. `tsconfig.json` extends `expo/tsconfig.base` and sets `checkJs: true`: the `.ts` files are real TypeScript, and `App.js`, `index.js`, `jest.setup.js`, `screens/**` and `components/**` are `.js` files that are still fully type-checked — not just parsed.
- **`.ts` files ignore JSDoc type annotations.** In a `.js` file `/** @type {X} */ (expr)` and `/** @type {Promise<unknown>} */ let q = ...` change the type; in a `.ts` file they are plain comments (this bit the Faz 22 conversion in 3 places — hence `mergeWordStatsIds`' real annotations and `as unknown as jest.Mock` in the tests). Use real annotations or `as` in `.ts`.
- It is deliberately **lenient**: `strict` and `noImplicitAny` are off. TS 6 turns those on by default and demands annotations on every parameter (measured: 161 extra `implicit any` errors on `services/` alone). `types: ["jest"]` is required, otherwise jest globals are unknown in `__tests__/` and `jest.setup.js`.
- `allowJs` and `noEmit` come from `expo/tsconfig.base` — `tsc` **never** writes `.js` output over the sources. Regenerate with `npx expo customize tsconfig.json`.
- It catches real API misuse (wrong React/RN calls, mistyped prop contracts — it found real bugs the day it was added). It does **not** cover runtime/device behaviour, JSON data shape, or anything not reachable from `include`.
- Type-only imports (`import type { X } from './y'`) are erased at build time, so a shared type never creates a runtime import cycle. `Word`/`WordId`/`WordLike` live in `services/wordRepository.ts` (imported, never re-declared, elsewhere).
- If you add a global type package, add it to `types` too.

## Rules

- Custom-deck word IDs (`custom_<sanitized name>_<item.id ?? index>`, `services/importService.ts`) are **identity**: review-pool and stats entries resolve by `wordId`, so never change the prefix rule without writing a migration. `saveCustomDeck` over-writes nothing silently (needs `{ overwrite: true }`) and rejects a name whose word IDs would collide with another deck. Deleting a deck goes through `deleteCustomDeck` only: it reads the deck's word ids **before** removing the deck (they are unreachable afterwards), prunes their stats itself, and returns `removedIds` so the caller can emit `onCustomDeckDeleted` — `App.js` owns `@hsk_review_pool` and drops the matching entries there. Pruning matches **exact ids**, never a prefix (`custom_Ders_` would also match another deck's `custom_Ders_1_5`).
- "Reset progress" (`clearAllStats()` + `onProgressReset`) clears stats **and** the mistake pool but never touches custom decks. Any new written copy of user progress must be cleared by it too. Since Faz 11 the button lives in `components/SettingsModal.js` only (it was in `StatsModal` before) — do not add a second copy.
- Settings are read **synchronously** at speak/vibrate time (`getCachedSettings()`), so `App.js` must keep priming the cache with `getSettings()` at startup, and any new setting must be added to `DEFAULT_SETTINGS` + the sanitizer in `services/settingsService.ts` rather than read from AsyncStorage directly.
- Never create or edit `android/` or `ios/` by hand — they are generated (Continuous Native Generation). Configure native behaviour in `app.json` and config plugins. (A stale `android/` folder exists locally; it is gitignored.)
- Home (`screens/HomeScreen.js`) is deliberately **non-scrollable** (a plain `View`, not a `ScrollView`): its content fits one screen on purpose. Anything added there must fit too — overflow is clipped, not scrollable. The level dropdown in `components/Header.js` is a list and still scrolls.
- Palette: red ramp `#991B1B` / `#DC2626` / `#B91C1C` / `#FCA5A5` / `#FEE2E2` / `#FEF2F2`, grey text `#2C3E50` (primary) and `#7F8C8D` (secondary), borders `#E2E8F0` / `#E9ECEF`, surfaces `#FBF5EB` / `#FFFFFF` / `#F8F9FA`. Emerald (`#047857` / `#059669` / `#ECFDF5`) is reserved for **correct** feedback — `components/QuestionCard.js` and `components/ScoreBoard.js` must keep the SAME values. Amber/gold tints belong only to Home's Custom Word Decks card; the quiz surface (`Header`, `QuestionCard`, `ExampleBox`, `QuizScreen`), `screens/VocabularyScreen.js` and the pop-ups (`StatsModal`, `SettingsModal`, `HandwritingModal`) are red (they were amber until Faz 12). `StatsModal`'s mastery bars and heat calendar are deliberately an ordered **red ramp** (darkening with HSK level / activity), with custom decks kept outside the ramp in `#2C3E50`; the heat thresholds live in both `HEAT_COLORS` and `getHeatColor()` — update them together.
- A pop-up whose content loads asynchronously (`components/StatsModal.js`) must have that content **ready before its entrance animation starts**: warm it while the modal sits closed, gate the animation on it, and keep a short (~150 ms) fallback so the card can never stay invisible. The card is sized to its content, so animating a small loading placeholder and then swapping in the real content makes the card grow and re-centre mid-flight — it reads as a glitch (Settings and the custom-deck pop-ups are unaffected: their content is synchronous).
- An absolutely positioned overlay inside a `ScrollView` is **clipped at the scroll view's bounds**, so its side and width must come from the measured layout, never be assumed: the calendar's day tooltip (`components/StatsModal.js`, `getTooltipLayout`) picks its side per column from the grid width measured with `onLayout`, narrows itself to the room left on that side, and shares its geometry constants (`CALENDAR_COLUMNS`, `CALENDAR_GAP`, `CALENDAR_PADDING`, `TOOLTIP_MIN_WIDTH`, `TOOLTIP_OFFSET`) with the stylesheet.
- Icons are drawn, not emoji, where a real brand mark exists: the GitHub button in `components/SettingsModal.js` renders the official "mark-github" octicon path through `react-native-svg` (already a dependency, used by `HandwritingModal`; no new package, works in Expo Go).
- Expo Go only ships its bundled native modules. Adding a library with native code requires a development build (`npx expo run:*`, or `eas build --profile development`) — unless the SDK docs mark it `inExpoGo: true` (e.g. `@react-native-community/slider`, added in Faz 11 for the speech-volume slider).
- App icons are **generated, never hand-edited**: `tools/generate-icons.py` (Python + Pillow — `python -m pip install pillow`) writes every PNG in `assets/`. `assets/icon.png` must stay **RGB without an alpha channel** (the App Store rejects transparency), the Android adaptive layers (`android-icon-foreground.png`, `android-icon-monochrome.png`) must keep the glyph inside the central **72/108 dp safe zone** (683 px of 1024), and `monochromeImage` must be a **single colour on transparency** (white — the launcher tints it), never a coloured drawing. Changing a colour or the glyph means editing the script and re-running it. `GLYPH_SCALE` is currently **0.42** (Faz 18 shrunk the glyph to 70% of its first size — 423×411 px of 1024); the same script also writes `assets/splash-icon.png` (the icon with rounded corners), which is the splash image. A new icon is only visible in a **development/EAS build** — Expo Go always shows its own icon (NOTES §19).
- The README gallery is **generated, never hand-edited** too (Faz 21): `tools/generate-store-screenshots.py` (Python + Pillow) turns the raw device captures in `docs/screenshots/raw/` into the 1080×1920 store-style `docs/screenshots/*.jpg` — it removes the **status bar (y 0-98) and the navigation bar (y 1932-2048)** per column (the bottom fill is read from *inside* the nav bar, y 1934-1952, so the app-window edge survives; saturated columns fall back to a neutral colour, otherwise a cut coloured button smears downwards), then adds the cream background, the phone frame (screen aspect **0.461** — never crop the capture), the 汉 badge, the caption and — only in the two **Statistics** images — the **sample progress** (HSK 1/2 100%, HSK 3 50%, a 38-day streak, 1-17 October heat calendar). That sample data must follow the app's own rules (`services/statsManager.ts` mastery, `components/StatsModal.js` colours/texts/thresholds) and stay **internally consistent** (streak ↔ calendar ↔ 7-day strip show the same days), and the README must keep the honest note that the frames are mockups and those two images use example data. Nothing is ever written into the app itself; the in-app text is drawn with `draw_text_ink()` at a font size calibrated against the real render's ink box (the device's font scale is large: 12dp ≈ 30 px em). The script prints `--debug` crops into `dist/store-debug/`. The gallery is **README-only**: it lives in `docs/` (never in `assets/`, which holds only the app icons and the splash) and no app code, `app.json` or `eas.json` entry references it, so it can never end up in the APK — it exists purely to promote the app in the repository. NOTES §25.
- The splash screen is configured by the **`expo-splash-screen` config plugin in `app.json`** (Faz 18): `backgroundColor` **`#FBF5EB`** — deliberately the same value as Home's surface and the navigation theme, so the hand-off is invisible — plus `./assets/splash-icon.png` and `imageWidth: 180`. `App.js` calls **`SplashScreen.preventAutoHideAsync()` at module scope** (inside a component it can be too late, per the Expo docs) and hides it after `SPLASH_MIN_MS` (1000 ms) with a 300 ms fade. Both calls swallow errors on purpose: a splash failure must never block startup. Like the name and the icon, the splash is a **native value** — Expo Go cannot show it.
- **Web is the second platform** (Faz 24): `npx expo export --platform web` writes a static `dist/` (gitignored) and `npx expo start --web` serves it. The native tree is untouched — `App.js` only wraps it in a centred `webFrame` (`maxWidth: 430` on a darker cream stage) when `Platform.OS === 'web'`.
- Two `react-native-web` traps fail **silently** and only on web, so never verify web by bundling alone — drive it in a real browser: **(1)** `Alert.alert` is a no-op (`static alert() {}`) → use `services/dialogService.ts`; **(2)** a `TouchableOpacity` with `disabled` renders a real `<button disabled>`, and Chromium delivers **no mouse events to buttons nested inside it** (pointerdown/up arrive, `mousedown`/`click` never do) → never put `disabled` on a touchable that wraps other touchables on web (the quiz card is the live example; `handleCardPress` already no-ops before answering).
- The vocabulary "Draw" search is hidden on web (`Platform.OS !== 'web'`): `inputtools.google.com` sends no CORS headers, and drawing with a mouse is not the point of the pad. Everything else (`expo-speech`, `expo-haptics`, `expo-clipboard`, `@react-native-community/slider`, `react-native-svg`, `DeviceEventEmitter`) has a web implementation — do **not** hide it.
- Headless-browser checks: give the page a viewport with `Emulation.setDeviceMetricsOverride` before clicking. Edge's `--window-size` is clamped on this machine (500×320), so clicks below the real viewport land on nothing and the app looks broken while it is not.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
- Never gate an external link behind `Linking.canOpenURL`: on Android 11+ it resolves `resolveActivity` to `null` (package visibility) and returns `false` in a standalone build, even though the phone has a browser — it only looked fine in Expo Go, whose own manifest declares the `<queries>` entry. Call `Linking.openURL` directly and handle the rejection (the settings GitHub row copies the address with `expo-clipboard` as a fallback). Same trap for any future `expo-web-browser`/`Linking` use.
- Accessibility: labels are **English** (matching the visible UI text). `TouchableOpacity` is an accessibility element by default (`accessible={this.props.accessible !== false}`) and therefore **hides its children** from screen readers — when a touchable wraps other touchables (the quiz card wrapping the option buttons in `QuestionCard`), keep it `accessible={false}` while those children must stay reachable. The floating-Hanzi background is decorative and must stay out of the accessibility tree (`accessibilityElementsHidden` + `importantForAccessibility="no-hide-descendants"`). `accessibilityState`/hints/announcements are not implemented yet.
- No emulator or device is attached to the development machine: device verification is done by the user, in Expo Go, on request.
- TypeScript split (Faz 22): new **logic** belongs in `services/` (or `data/examples/`) as `.ts`; screens and components stay `.js`/JSX (React Navigation + `Animated` are JS-shaped) but are still checked via `checkJs`. Never re-declare a shared type — import it (`Word`, `WordId`, `WordLike` from `services/wordRepository.ts`; `QuizMode`/`QuizCategory`/`FieldType` from `services/modes.ts`; the stats record shapes from `services/statsManager.ts`). Follow the local convention for exported helpers: real parameter/return annotations on the public API, `any` only at a genuine trust boundary (raw `JSON.parse` output, legacy stored records) with a comment saying why. `npm run lint` treats `@typescript-eslint/array-type` as a warning, so use `T[]` and not `Array<T>`.

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run the EAS CLI as `npx eas-cli@latest <command>` (this project uses npm), substituting it for the bare `eas` in the docs. Docs: https://docs.expo.dev/eas/index.md

- **`eas.json` exists** (Faz 16, `bf3e7a2`): `preview` = internal distribution → a shareable **APK** (no store needed); `production` = store build (AAB) with `autoIncrement`; `cli.appVersionSource: "remote"` keeps `versionCode`/`buildNumber` on EAS, so they are deliberately absent from `app.json`. `submit.production.android.track: "internal"` keeps the first Play upload on the internal testing track.
- **There is no `development` profile on purpose:** `developmentClient: true` requires the `expo-dev-client` dependency, which is not installed (the test loop is still Expo Go). Add the dependency and the profile together when a native module needs a dev build.

## Workflow

- Work directly on `main`; **one commit per fix**, with a descriptive message.
- The `known-good` tag marks the last verified state. Advance it only once `npm test` / `npm run lint` / `npm run tsc` are green and the user has confirmed the device check; roll back with `git reset --hard known-good`.
- `.git/hooks/post-commit` (local only) pushes `main` and the `known-good` tag after every commit.
- `NOTES.md` is the handoff document — read it first, update it when a phase lands.
- The repository is **public** (Faz 19) and doubles as the app's front page. `README.md` is a **live document**: update it whenever a command, script, dependency or the test count changes. Its audience is the **end user first**: the opening section is *Download & install* (the APK attached to the latest GitHub release, Android 7.0+), and the Expo Go / `npm install` instructions stay under *Building from source* for developers — keep that order when editing it, and attach every new Android build to a GitHub release (`releases/latest` is what the README's download badge and section link to; an EAS artifact URL expires after ~30 days). `.github/workflows/ci.yml` runs `npm ci`, `npm run lint`, `npm run tsc` and `npm test` on Node 22 for every push to `main` and every pull request — **keep it green** (the README's CI badge shows its real state). `expo-doctor` is deliberately not in CI: the known `tsc` script-name clash makes it exit 1 even though everything is healthy (NOTES §16). The repo description and topics are GitHub settings, not files.
- Keep exactly one `ChineseQuizApp-backup-*.tar.gz` in `C:\Projects\App`: delete the older archive when taking a new one. (The archive is named after the local folder, which is still `ChineseQuizApp` even though the app and the repo are `hanyupick`.)
- `eslint.config.js` deliberately relaxes three rules, with the reasons inline: `react-hooks/refs` is off (the code uses React Native's `Animated` ref API, which the rule cannot model), and `react-hooks/set-state-in-effect` / `react-hooks/exhaustive-deps` are warnings rather than errors. `npm run lint` is expected to stay at **0 errors**.
